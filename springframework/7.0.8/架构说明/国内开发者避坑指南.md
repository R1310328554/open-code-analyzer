# Spring Framework 7.0.8 —— 国内开发者避坑指南

> 目标：把「会用注解」升级成「看得出源码在干什么」。

## 1. 别从注解开始读，从生命周期开始读

常见误区：一上来搜 `@Autowired` 实现，越看越散。  
推荐顺序：

1. `AbstractApplicationContext#refresh`
2. `AbstractBeanFactory#doGetBean`
3. `AbstractAutowireCapableBeanFactory#doCreateBean`
4. `DefaultSingletonBeanRegistry` 三级缓存
5. 再看 `AutowiredAnnotationBeanPostProcessor`

## 2. 「注入失败」通常不是注解写错，而是候选决策失败

`DefaultListableBeanFactory#doResolveDependency` 会处理：

- 类型匹配不到 / 匹配到多个
- `@Primary` / `@Priority` / 字段名回落
- `ObjectProvider` / `Optional` / 集合注入

建议：把异常栈里的 bean 名与 requiredType 对照 `beanDefinitionMap`，而不是反复改注解位置。

## 3. 循环依赖：单例字段注入能救，构造器注入救不了

- 单例 + setter/字段：早期引用（三级缓存）可能解开
- 构造器互相依赖：创建前就要对方实例 → 通常直接失败

这是生命周期约束，不是“Spring 不够智能”。

## 4. `@Transactional` 自调用失效

同类中 `this.method()` 不经代理，事务拦截器不触发。  
解法思路：拆 Bean、注入自身代理、`AopContext.currentProxy()`（需 expose-proxy）。

## 5. `@Configuration` 的 FULL vs LITE

- FULL（经典 `@Configuration`）：CGLIB 增强，`@Bean` 互调走容器
- LITE（如普通 `@Component` 里声明 `@Bean`）：互调就是普通 Java 调用

看 `ConfigurationClassPostProcessor#enhanceConfigurationClasses`。

## 6. MVC 调试先抓住 doDispatch

请求问题 80% 可在 `DispatcherServlet#doDispatch` 分段定位：

映射不到 → HandlerMapping  
进不去方法 → Adapter / 参数解析  
返回奇怪 → MessageConverter / ViewResolver  
异常页不对 → HandlerExceptionResolver

## 8. 建议的精读清单（本版本）

1. `AbstractBeanFactory#doGetBean`
2. `DefaultSingletonBeanRegistry#getSingleton`
3. `AbstractAutowireCapableBeanFactory#doCreateBean`
4. `DefaultListableBeanFactory#doResolveDependency`
5. `AbstractApplicationContext#refresh`
6. `ConfigurationClassPostProcessor`
7. `JdkDynamicAopProxy#invoke` / `CglibAopProxy`
8. `DispatcherServlet#doDispatch`
9. `TransactionAspectSupport#invokeWithinTransaction`

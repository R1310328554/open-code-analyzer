# open-code-analyzer
各类著名的开源软件项目、框架的架构分析、关键技术详解、逐行解读

每个目录就是 开源项目，每个项目 可以有多个各种 tag， 项目的目录下面是版本号， 再下面是original， 即那个项目的那个 的具体原始的源代码。还有一个目录是 analyzed 目录， analyzed 目录和 original 目录 一模一样，但是每个文件、每个方法都要做解析，分析它的用途、意图、并为其添加中文注释、说明、解析。如果 类、方法上面已经有注释、说明，那么就添加到它的原始的注释说明之前。 方法内部也可以添加注释、说明、分析，每一行代码都可以添加， 只要是它很复杂，达到一定的复杂度，很难理解，就添加。

如，我说，分析springframework 6.0.0 的源码 ， 那么就创建如下目录结构：

springframework
    6.0.0
        original    // 这里放 对应版本的原始的源码， 只读， 不做任何改动。
        analyzed    // 这里首先也是放原始源码， 然后需要使用ai 等各种工具，对其中每个文件、每个类、方法、脚本做分析，得知其意图、用法，然后添加的 方法的注释之中。


如果我说分析 springframework 的最新源码， 那么可以先找到github上 springframework 的仓库地址，确认后， 分析它的当前最后一个Release 版本的源码， 它的当前最新的一个 Release的版本号， 作为我们的具体的版本号。 

如果我说分析 spring 的最新源码， 那么这个时候就比较模糊了， 需要进一步确认到底是哪个  spring 项目的源码， 提示给出开源项目的 github 或gitee 地址。

如果我说分析 java 的最新源码， 那么这个时候就比较模糊了， 需要进一步确认到底是哪个java 项目的源码， 是openjdk ？ 还是 阿里的jdk ？ 是java 中log4j， 还是其他的什么java 项目？

如果我指明了具体的github 项目的链接，那么就分析它的当前最后一个Release 版本的源码。 如果它没有任何Release， 那么就分析它的最新一层的代码。-- 不要完整的 clone拉取， 只需要clone depth=1。


说明， 关键是需要判断类、方法的复杂度，如果太简单了， 比如 一个简单java类， 其中20个字段，那么每个字段一个没有任意营养价值的 getter、 一个setter， 那么这些getter、 setter 自然就不需要添加任何注释、说明。 当然，每个字段的还是需要一个简单的中文说明的， 需要指明它的含义、意图。
